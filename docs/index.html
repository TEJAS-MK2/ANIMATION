Motion that ships.

03 / GUIDES

Build motion responsibly.

Performance

Prefer transforms and opacity. Avoid unnecessary layout work and continuous effects that consume CPU when they are not visible.

Customization

Use the playground controls to explore timing, scale, radius, intensity, and component-specific parameters before adapting the source.

Frameworks

Reference implementations are available for HTML, CSS, JavaScript, React, and Tailwind. See the v1.1 UI primitive recipes for practical framework guidance.

05 / ACCESSIBILITY

Motion should be optional.

Non-essential animation should respect prefers-reduced-motion. Interactive components should remain usable with keyboard and touch input, and motion should never be the only way information is communicated.

Read accessibility guidance ↗
06 / CONTRIBUTING

Make the library better.

New components and templates should be responsive, maintainable, reasonably performant, accessible, and properly licensed.
