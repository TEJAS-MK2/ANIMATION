# Security Policy

## Supported versions

ANIMATION is currently under active development. Security fixes are prioritized for the latest version on the `main` branch.

## Reporting a vulnerability

Please **do not open a public GitHub issue for an undisclosed security vulnerability**.

For a private report, use GitHub's repository security reporting features if they are enabled for this repository. If private reporting is unavailable, contact the project maintainer through the contact method listed on the repository profile and provide only the information necessary to reproduce and assess the issue.

When reporting, include:

- A concise description of the vulnerability.
- Affected file, component, or feature.
- Reproduction steps or a minimal proof of concept.
- Potential impact.
- Suggested mitigation, if known.

Please do not include passwords, access tokens, private keys, personal data, or other secrets in a report.

## What to expect

Maintainers will review valid reports, investigate the affected code, and coordinate a fix or mitigation when appropriate. Please allow reasonable time for investigation before publicly disclosing the vulnerability.

## Scope

Security reports may include issues such as:

- Cross-site scripting (XSS).
- Unsafe DOM manipulation.
- Dependency or supply-chain vulnerabilities.
- Malicious or unexpected network requests.
- Credential or secret exposure.
- GitHub Actions or deployment security issues.
- Vulnerabilities in downloadable or generated component code.

Visual bugs, ordinary functional bugs, and feature requests should normally be reported through GitHub issues instead.
